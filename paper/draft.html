Abstract

We study whether the hierarchical structure of a legal code and a citation/application knowledge graph (KG) improve retrieval-augmented question answering (RAG) over the Thai Penal Code. We compare a strong dense–sparse hybrid retriever against two structural signals — PageIndex tree navigation and one-hop KG expansion — on a 255-item, gold-by-construction benchmark spanning six question types, with a fixed Thai open-model generator and a separate-vendor LLM judge. Our central finding is a design principle: structural signals help only when they augment the hybrid retriever, not when they replace it. A PageIndex-only pipeline reaches just 0.350 answer accuracy; naively substituting PageIndex for hybrid in the "full" system makes it the worst real configuration. Recast additively — union the hybrid and PageIndex pools, then append KG-selected supporting provisions into a reserved rank slot — the full system (HYBRID+PI+KG) becomes the best real arm at 0.718 answer accuracy, the only configuration to beat the hybrid baseline with Holm-corrected significance (Δ = +0.082, p = 0.006), closing 35% of the gap to an oracle-context ceiling (0.809). A controlled comparison that holds the primary evidence fixed isolates the KG contribution as multi-hop-specific (+0.178 on multi-hop items) rather than a uniform gain, and confirms the reserved slot's context reduction is inconsequential (Δ = −0.005). Five ablations and a fault decomposition show the residual gap is bounded by KG edge precision — the correct supporting provision is 100% reachable but out-ranked among ~271 over-generic APPLIES_TO neighbours — not by candidate depth, context size, or the generator. We release the benchmark, pipeline, and a reproducible run snapshot.

Contributions. (1) An additive structure-aware RAG design with a reserved-slot KG expansion that adds multi-hop context without displacing primary evidence. (2) A controlled 2×(hybrid/PI) × (KG on/off) study on Thai statutory QA with paired significance testing. (3) A fault decomposition localising the remaining error to KG edge precision, turning a data limitation into a concrete, actionable direction.

1. Introduction

Statutory question answering is retrieval-bound: a language model rarely recalls exact section numbers, penalty figures, or inserted provisions (ทวิ/ตรี) reliably, so answer quality hinges on surfacing the right มาตรา. The Thai Penal Code adds two structural affordances a flat retriever ignores: a hierarchy (ภาค → ลักษณะ → หมวด → มาตรา) and a web of cross-references and general provisions (limitation, principals/accessories, attempt, aggravating/mitigating factors) that a correct answer must combine with the operative offence.

We ask whether exploiting this structure improves RAG, via five questions: RQ1 does PageIndex tree navigation beat a dense–sparse hybrid at finding the answering section; RQ2 does one-hop KG expansion recover the general provisions needed for multi-hop reasoning; RQ3 does better retrieval translate into a more faithful generated answer under a fixed generator; RQ4 what does each structural layer cost; RQ5 how much does retrieval matter at all given likely pre-training exposure.

Our answer to RQ1 is nuanced and, we believe, the paper's main lesson: PageIndex loses badly as a replacement for hybrid retrieval, but contributes as an additive signal on top of it. The same holds for KG. This reframes "structure-aware retrieval" from choosing a structural retriever to composing structural signals with a strong lexical–dense base.

3. Method

3.1 Corpus and artifacts

We use the Thai Penal Code (ประมวลกฎหมายอาญา) from PyThaiNLP criminal-csv-v0.1, 444 sections. An ingest pipeline produces: sections.jsonl (one record per มาตรา — the shared chunk unit for every retriever, removing granularity as a confound); penal_tree.json (the ภาค→…→มาตรา hierarchy, the search space for PageIndex); and a knowledge graph of CITES edges (719) and APPLIES_TO edges (13,296) linking general provisions to the offences they govern.

3.2 ชุดข้อสอบสำหรับประเมินผล (Evaluation set)

เราสร้างชุดข้อสอบทองคำ 255 ข้อบนประมวลกฎหมายอาญา (444 มาตรา) ด้วยหลักการ "gold-by-construction" คือเฉลยของการค้นคืนถูกกำหนดโดยการออกแบบ ไม่ใช่ให้โมเดลเลือก สำหรับแต่ละข้อ เราเป็นผู้เลือกมาตราที่เป็นคำตอบเองก่อน แล้วจึงส่งเฉพาะตัวบทของมาตรานั้น ให้แบบจำลองผู้ร่าง (drafter) เขียนเพียงคำถามภาษาธรรมชาติ คำตอบอ้างอิง และชุดข้อความ ย่อยที่ตรวจการอ้างอิงได้ (answer_claims) โดยทั้งหมดต้องมีที่มาจากตัวบทที่ให้เท่านั้น เนื่องจาก gold_sections (และ supporting_sections สำหรับข้อประเภทหลายมาตรา) ถูกกำหนด โดยเรา เฉลยการค้นคืนจึงไม่มีทางเป็นการแต่งเติมของโมเดล อีกทั้งผู้ร่างไม่ใช่แบบจำลองที่ ถูกทดสอบ (generator) และไม่ใช่กรรมการ (judge) จึงไม่เกิดการปนเปื้อนแบบวงจรประเมินตนเอง แต่ละข้อถูกสร้างเป็น JSON ตามสคีมา (question, reference_answer, answer_claims, difficulty) และผ่านตัวตรวจสอบสคีมา/ความสอดคล้องที่จะปฏิเสธข้อที่มาตราเฉลยไม่มีอยู่จริง ในคลังข้อมูล

ชุดข้อสอบครอบคลุม 6 ประเภทตามจำนวนเป้าหมายที่กำหนดไว้: lookup (75) ค้นหามาตราตรง, penalty (55) ฐานความผิด/อัตราโทษ, multi_hop (45) ต้องใช้หลายมาตราประกอบ, unanswerable (35) คำถามนอกขอบเขตเพื่อทดสอบการปฏิเสธ, exception (25) เหตุยกเว้นความผิดหรือโทษ, และ definition (20) ความหมายตามบทนิยาม เราสร้างชุดผู้สมัคร (pool) ของแต่ละประเภทจากคลังข้อมูล ด้วยการกรองเชิงโครงสร้างและคำสำคัญ แล้วสุ่มแบบแบ่งชั้น (stratified) กระจายข้ามลักษณะ (titles) ด้วยค่า seed คงที่ เพื่อไม่ให้ข้อกระจุกอยู่บริเวณเดียวและทำให้ชุดข้อสอบสร้างซ้ำได้ ประเภท lookup/penalty/exception คัดจากมาตราที่มีโทษหรือเป็นเหตุยกเว้นในภาค 2-3, definition คัดจาก มาตราบทนิยาม, unanswerable คัดจากหัวข้อนอกกฎหมายอาญา (ภาษี แรงงาน แพ่ง คนเข้าเมือง ฯลฯ) ส่วน multi_hop สร้างโดยจับคู่ฐานความผิดในภาค 2 (เป็น gold) กับบทบัญญัติทั่วไปในภาค 1 (เป็น supporting) ได้แก่ การพยายาม (ม.80) ตัวการ (ม.83) ผู้ใช้ (ม.84) ผู้สนับสนุน (ม.86) หลายกรรม (ม.91) หรือการเพิ่มโทษเมื่อกระทำผิดอีก (ม.92) เพื่อให้การตอบที่ถูกต้องต้องอ้างทั้ง ฐานความผิดและบทบัญญัติทั่วไปที่เกี่ยวข้องประกอบกัน

3.3 Retrieval components

  • Hybrid. BM25 (lexical) fused with BGE-M3 dense similarity (min–max normalised, α = 0.5), surfacing a pool of POOL = 50 candidates, then a Qwen3 cross-encoder reranker.
  • PageIndex (PI). The generator LLM descends penal_tree.json with beam width 5, selecting sections by reasoning over node headings.
  • KG. One-hop expansion along CITES ∪ APPLIES_TO from a seed set, growing the candidate pool with cited/applicable provisions before reranking.

3.4 Additive system design and reserved-slot KG

The key design choice is additive composition. Rather than treating PageIndex as an alternative base retriever (a replacement 2×2), we union the hybrid pool with PageIndex-selected sections and rank the result — hybrid's recall becomes a floor the structural signal can only raise. KG is then applied as a reserved-slot append: we rank the primary (hybrid ∪ PI) pool cleanly, take its top k−1, and append the single best KG-surfaced supporting provision into the k-th slot. This lets KG add multi-hop context without ever displacing a primary gold section, and mirrors the oracle's gold ∪ supporting context construction. When KG surfaces nothing new, the arm falls back to the top-k primary ranking.

Figure 1. The additive pipeline. Hybrid and PageIndex candidates are unioned, then reranked into k−1 primary sections plus one reserved slot holding the best KG-expanded supporting provision. Structure augments the strong hybrid base rather than replacing it; the generator is fixed across all arms.

3.6 Generation and judging

A single Thai open model, Qwen3.6-35B-A3B at temperature 0, generates all answers from the top-k=5 retrieved sections with one shared prompt across arms (no question-type leakage). The same model drives PageIndex navigation (no cross-arm confound). A different-vendor judge, DeepSeek-V4-Pro, scores answer correctness (binary + 1–5) and per-claim grounding, avoiding self-preference bias. Embedder: BGE-M3; reranker: Qwen3-Reranker-4B. All models served on a single provider (DeepInfra).

3.7 Metrics and statistics

Retrieval: recall@5, MRR@10, coverage@5 over gold ∪ supporting, and support-recall@5 over supporting. Generation: judge answer-accuracy, claim-grounding rate, hallucinated-section rate. Every item passes through every arm (within-subjects/paired). We report 95% paired bootstrap CIs (10k resamples), McNemar exact tests for paired binary contrasts, and Holm–Bonferroni FWER control over the contrast family.

4.4 Controlled comparison: isolating the KG contribution

The HYBRID+PI+KG − HYBRID+PI contrast confounds two simultaneous changes: the reserved slot both (i) appends a KG supporting provision and (ii) reduces the primary sections shown to the generator from five to four (the fifth slot is spent on KG). We disentangle them with two controlled runs that share the same generator and judge.

(i) Context size is inconsequential. Feeding HYBRID+PI its top-4 instead of top-5 sections moves accuracy from 0.673 to 0.668 (Δ = −0.005). Dropping the fifth primary section costs essentially nothing, so the reserved slot's context reduction is not the source of the effect.

(ii) The KG effect, holding primaries fixed. We take the full system's own four primary sections and compare generation with vs. without the appended KG slot — an item-wise paired contrast over identical primary evidence. KG raises accuracy from 0.695 to 0.718 (Δ = +0.023; McNemar exact p = 0.46, not significant), but the effect is strongly heterogeneous by type:

exception 0.760 0.720 −0.040

Figure 3. KG contribution by question type, holding the four primary sections fixed (KG on − KG off). The gain is concentrated on multi_hop (+0.178), the type that needs a Book-1 general provision; single-section types (penalty, exception) see small losses from the appended provision acting as a distractor. The net effect is small and non-significant.

KG delivers a large gain precisely where it is designed to help — multi-hop items that require a Book-1 general provision (+0.178) — but injects distracting provisions on single-section types (penalty, exception), so the net increment is small and non-significant. This matches the edge-precision diagnosis (§5): the appended provision helps only when the query genuinely needs a supporting section. We therefore report the KG contribution as multi-hop-specific rather than a uniform lift, and note that a query-adaptive KG gate is the natural remedy (§8). Because the two top additive arms are already statistically tied (Table 2), this controlled result refines why: their difference is a type-dependent redistribution, not a uniform improvement.

5. Ablations

Four interventions attempt to push past 0.718; all fail, and all for the same reason — they feed more into KG expansion, amplifying over-generic APPLIES_TO edges (mean ~271 neighbours/node, 0 verified) that drown the one relevant provision.

Context size k=5 / k=3 / k=2 0.668 / 0.668 / 0.636 trimming ≤ 0

KG reserved slots 1 / 2 0.718 / 0.702 −0.018

Notably, POOL=100 raises recall@5 (0.932 → 0.945) yet lowers accuracy — the larger seed expands into more KG noise and multi_hop collapses (−0.111). Recall is not the binding constraint; KG precision is.

A recall–accuracy frontier. recall@5 and MRR@10 credit only the primary answering section, whereas the reserved slot deliberately spends one of k positions on a KG supporting provision. The full system is therefore best on coverage@5 (0.850) and support-recall@5 (0.556) but not on recall@5 (0.932 vs 0.950 for HYBRID+PI). An adaptive gate that reserves the KG slot only when its candidate out-scores the cut-off primary attains the highest recall@5 of any arm (0.955) — yet accuracy falls to 0.686, because it withholds relevant-but-lower-scored provisions the multi-hop items need (support-recall 0.556 → 0.400). The two objectives are not jointly maximisable: forcing the supporting provision in is accuracy-optimal, gating it out is recall-optimal. We report the accuracy-optimal configuration; its recall@5 shortfall is a deliberate reallocation of retrieval budget from primary to supporting evidence.

Multi-hop fault decomposition. multi_hop accuracy is 0.489 vs 0.778 oracle. Of the errors, 33% are retrieval faults (supporting provision absent from top-5) and 18% are generation faults (present but unused). Every missing supporting provision is 100% reachable in the KG from the gold section — it is simply out-ranked among the ~271 neighbours; and 51% are reachable only via generic all_offences edges, so naive pruning is not viable. The bottleneck is edge precision, addressable by curation, not by a pipeline hyperparameter.

6. Discussion

The results recommend a shift in how "structure-aware retrieval" is framed: not as selecting a structural retriever, but as composing structural signals over a strong base. PageIndex and KG each encode real legal structure, yet each underperforms hybrid alone; their value is realised only additively, and only when integration preserves primary evidence (the reserved slot). The full system's significance-over-baseline arising only from the combination suggests the structural signals are complementary rather than redundant, despite pairwise ties at this sample size.

The controlled comparison (§4.4) sharpens this: KG is not a uniform improvement but a type-specific one — a large gain on multi-hop items (+0.178), which need a Book-1 general provision, offset by small losses on single-section types where the appended provision is a distractor. A static reserved slot therefore trades correctness across types; a query-adaptive gate that admits the KG provision only when the question needs one is the principled next step, and is currently limited less by the gating rule than by the precision of the underlying edges.

The ceiling analysis is equally instructive: with the recommended system, primary retrieval is nearly solved (recall 0.932; POOL=100 shows it can reach 0.945), and the residual gap to oracle is concentrated in multi-hop reasoning and bounded by KG edge precision. This localises future effort precisely.

7. Limitations

  • Judge validation. Answer-accuracy and claim-grounding derive from an LLM judge (a different vendor from the generator, mitigating self-preference). A blind human expert audit of 150 items is in progress (§4.3); provisional agreement against a second-model proxy is substantial overall (κ ≈ 0.73) but weak on multi-hop (κ ≈ 0.20), so multi-hop conclusions are stated with caution pending the final human κ.
  • KG edges are unverified (verified = 0 of 13,296 APPLIES_TO). RQ2 uses automatically extracted edges; the over-generic all_offences scope is the identified precision bottleneck.
  • Single generator, single corpus, single statute version. Robustness replication with a second Thai model and generalisation beyond the Penal Code are left to future work.
  • Statistical power. At n = 220 the top additive arms cannot be separated; the full system's advantage is established over the baseline, not over HYBRID+PI.
  • Scope. We report answerable QA; the unanswerable/refusal analysis is deferred (its deterministic refusal metric is not yet reliable).

8. Future Work

Our diagnosis makes the highest-value directions concrete rather than open-ended:

  • KG edge curation (primary lever for multi-hop). The residual multi-hop gap is bounded by the precision of APPLIES_TO edges, of which the all_offences scope (67% of edges, ~271 neighbours/node) is near-complete and un-discriminative. A lawyer-verified pass — pruning generic scopes and confirming the specific book2/by_penalty edges — should let a reserved or adaptive KG slot surface the right supporting provision reliably. Handling the small set of universal provisions (limitation, principals/accessories, attempt) as query-triggered inclusions rather than dense edges is a lighter-weight alternative.
  • Judge validation at scale. Extend the blind expert audit and add a second legal annotator on an overlapping subset to report inter-annotator agreement alongside human–judge agreement, strengthening the evaluation instrument.
  • Unanswerable / refusal handling. Repair the deterministic refusal metric so the unanswerable type re-enters the analysis (currently scoped out).
  • Statistics and cost. Fit the pre-registered 2×2 GLMM interaction (we report a bootstrap difference-in-differences); complete the RQ4 cost/latency roll-up (LLM calls/query, p95 latency, index build) from the logged per-query metadata.
  • Robustness and generalisation. Replicate with a second Thai generator; enlarge the eval set to separate the top additive arms (tied at n = 220); and extend beyond the Penal Code to a second statute to test that the additive principle transfers.
  • Retrieval refinements. Query decomposition for multi-hop, and a tuned adaptive KG gate on curated edges (§5), toward closing the recall–accuracy trade-off rather than sitting on it.

9. Conclusion

On Thai statutory QA, hierarchical and knowledge-graph structure improve retrieval-augmented answering only additively: replacing a strong hybrid retriever with structure is strictly worse, whereas composing structure over it — with KG appended into a reserved rank slot — yields the only configuration to beat the hybrid baseline with corrected significance, at 0.718 accuracy against an 0.809 ceiling. Ablations localise the remaining gap to knowledge-graph edge precision, a curation problem rather than a modelling one.
